**Invariants** are the properties that must hold **always**. Each has a stable number and the test that checks it; the
full list, with status and test names, is in `docs/invariants.md`. A change touching availability, prices, bookings or
payments must leave them all valid (in Claude Code the `invariants-guardian` subagent checks it).

## How they are checked

- **Unit**, table-driven, `TestXxx_Scenario`; **property-based** with `pgregory.net/rapid` for prices and
  availability.
- **Integration** with the `integration` build tag: in-memory SQLite always, PostgreSQL when
  `ARENILE_TEST_POSTGRES_URL` is set (`make test-db` starts the container).
- **Concurrency**: `TestConcurrency_*` tests with `-race` and at least 100 parallel attempts on the same resource
  (`make test-race`), including desk versus online on the same spot.
- **Acceptance**: `internal/acceptance` starts the real application with a fake clock, uses it only through the APIs
  (hundreds of operations, concurrent bursts) and checks the invariants on the database, on both dialects.

<Aside type="note">
  A new invariant is appended with the next number, together with its test; numbers are never reused.
</Aside>
