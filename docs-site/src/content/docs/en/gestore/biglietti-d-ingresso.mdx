**Where:** Configuration → **Entry tickets** (types), **Quick sale** → **Entries** tab (sale), **Quick sale** →
**Gate** (check). **Who:** managers and owners configure; cashiers sell and check.

For an equipped free beach or a pool you sell an **entry**, not an umbrella. Arenile sells entries with the same daily
numbering as tickets and checks them at the entrance by reading the QR code: **one entry per ticket**.

## Before you start

<Steps>

1. A [zone](/en/gestore/zone/) in **quantity** mode (for example *Equipped free beach*) with its
   [pool](/en/gestore/pool/): the pool capacity is the **daily capacity**, shared with online sales.
2. A [catalog](/en/gestore/catalogo/) component that uses that pool and a **pack** for each entry type (for example
   *Adult entry*), priced in the [price list](/en/gestore/prezzi/) by rate period.

</Steps>

## Entry types

In **Entry tickets** → **New type**: **Code** (for example `adulto`, fixed after creation), **Name** and
**Description** in the establishment languages, **Pack**, **Zone**, **Order** and **Active**. Only active types appear
in the sale. A type that was already sold cannot be deleted: deactivate it.

<Screenshot name="admin-entry-types" alt="Entry ticket configuration with the Adult and Child types" />

## Selling entries

<Steps>

1. **Quick sale** → **Entries** tab.
2. Choose the **Slot** (full day, morning, afternoon) and the quantities per type with the + and − buttons.
3. Arenile shows the total from the price list and the **places left**; when capacity runs out the sale is blocked.
4. Optional name, then **Cash** (with the register open and the change) or **Card** and **Collect**.

</Steps>

<Screenshot name="admin-entry-sale" alt="Quick sale, Entries tab: quantities per type, places left and total" />

One ticket covers everybody in the sale (*3 people*) and prints like the other tickets. If two registers sell the last
place at the same moment, only one sale goes through: the database checks the capacity.

## Gate control

**Quick sale** → **Gate** (or the command search) opens the page for the staff phone.

<Screenshot name="admin-entry-gate-mobile" alt="Gate on a phone: QR reading or the ticket code typed by hand" />

- **Start camera** and frame the ticket's QR code (Chrome or Edge on Android and desktop), or type the **day
  number** printed large on the ticket (e.g. `37`) or the booking code and tap **Confirm entry**.
- Results: **Valid entry** (with number and people), **Already entered** (with the time of the first entry), **Ticket
  voided**, **Ticket for another day**, **Ticket not found**. Where the phone supports it (Android) a vibration goes
  with the result; on iPhone read the screen.
- The same reading repeated within 4 seconds is ignored: no double results while the QR stays in frame.
- One ticket covers everybody in the sale: **one scan admits the group** (the result shows how many people).

<Aside type="caution" title="iPhone and Firefox: manual entry">
  Safari on iPhone and Firefox cannot read QR codes with the camera: the page says so and the staff types the ticket
  number. The QR holds a random code, so only a scan admits on its own; a typed number or code goes through only with
  **Confirm entry**, recorded in the history as a manual entry.
</Aside>
