Arenile segue il **versionamento semantico** (`MAGGIORE.MINORE.PATCH`). Le migrazioni del database sono
**sempre compatibili in avanti** e vengono applicate in automatico all'avvio: aggiornare significa scaricare la
nuova versione e riavviare.

## Procedura consigliata

<Steps>

1. **Leggi le note di versione** nella pagina [Novità](/installazione/novita/) (e nel `CHANGELOG.md` del
   repository), soprattutto prima di un aggiornamento di versione minore o maggiore.

2. **Fai un backup**:

   ```bash
   cd /opt/arenile
   docker compose exec arenile /arenile backup --out /data/backup/pre-update-$(date +%F).db
   ```

3. **Aggiorna e riavvia**:

   ```bash
   docker compose pull
   docker compose up -d
   ```

4. **Verifica**:

   ```bash
   docker compose exec arenile /arenile version
   curl -fsS https://prenota.mio-lido.it/readyz
   ```

</Steps>

<Tabs>
  <TabItem label="Versione fissata (consigliato)">
    In produzione fissa una versione precisa in `.env` e cambiala tu quando decidi di aggiornare:

    ```ini title=".env"
    ARENILE_VERSION=0.4.2
    ```
  </TabItem>
  <TabItem label="Sempre l'ultima">
    Con `ARENILE_VERSION=latest` (predefinito) ogni `docker compose pull` porta l'ultima versione pubblicata.
    Comodo su un'istanza di prova, sconsigliato in alta stagione.
  </TabItem>
  <TabItem label="Dai sorgenti">
    ```bash
    git fetch --tags && git checkout v0.4.2
    make build
    sudo systemctl stop arenile
    sudo install bin/arenile /usr/local/bin/arenile
    sudo systemctl start arenile
    ```
  </TabItem>
</Tabs>

## In alta stagione

- Aggiorna in un momento di basso traffico (sera o mattina presto), mai durante l'apertura della cassa.
- Preferisci le versioni di **patch** (correzioni) e rimanda le minori a fine stagione, salvo correzioni di
  sicurezza.
- Durante il riavvio (pochi secondi) la pagina pubblica non risponde: i clienti a metà prenotazione ritrovano
  il blocco del posto finché non scade.

## Tornare indietro

Le migrazioni vanno solo in avanti: una versione precedente non sa leggere uno schema più nuovo. Per tornare
indietro **ripristina il backup** fatto prima dell'aggiornamento e avvia la versione precedente (vedi
[Backup e ripristino](/installazione/backup-e-ripristino/)).

<Aside type="tip">
  `arenile migrate status` mostra le migrazioni applicate e quelle in attesa; con
  `ARENILE_AUTO_MIGRATE=false` puoi applicarle a mano con `arenile migrate up` prima di avviare il server.
</Aside>

## Avviso di nuova versione

Quando esce una nuova versione, titolari e gestori vedono in cima al pannello **È disponibile Arenile X** con
**Novità** e **Come aggiornare** (installazione Docker: porta a questa pagina; ricordati del backup, poi
`docker compose pull && docker compose up -d`) oppure **Scarica** (app desktop e binario). L'avviso compare pochi secondi dopo
l'avvio del server, senza ricaricare la pagina, si chiude con la **X** e torna solo per la versione successiva.

Tutto è riassunto nella pagina **Informazioni su Arenile** (menu dell'utente in basso a sinistra, o **Dettagli**
nell'avviso): versione in uso, edizione, stato del controllo con l'ora dell'ultimo controllo, ultima versione
pubblicata con le **Novità**, il pulsante **Verifica aggiornamenti** per controllare subito (il server ne esegue al
massimo uno al minuto) e l'azione per aggiornare: **Come aggiornare** con Docker, **Scarica Arenile X per
…** (per esempio *per macOS (Apple Silicon)*) con l'app desktop e il binario, più **Tutte le versioni e i sistemi**
([arenile.app/download](https://arenile.app/download/)). Nell'app desktop la stessa pagina è anche nel menu
dell'icona e nel menu **Arenile** su macOS, e la notifica di nuova versione apre direttamente questa pagina.

Il controllo è **acceso di default**: una volta al giorno Arenile legge il file pubblico
`https://updates.coste360.it/arenile/latest.json`. La richiesta non contiene dati del lido, cookie né
identificativi: rivela solo la versione, l'edizione e il sistema operativo nell'User-Agent (per esempio
`arenile/1.0.1 (server; linux/amd64)`) e, come ogni richiesta HTTP, l'indirizzo IP al server di Coste360, che usa
queste informazioni solo per conteggi aggregati. Non è telemetria: `ARENILE_TELEMETRY` resta `false`.

Per spegnerlo imposta `ARENILE_UPDATE_CHECK=false` (nessuna chiamata di rete); con `ARENILE_UPDATE_URL` puoi
puntare a un mirror interno. Se il controllo non riesce (niente internet, server non raggiungibile) il pannello non
mostra errori: nel menu dell'utente e in **Informazioni su Arenile** compare solo "Impossibile cercare
automaticamente gli aggiornamenti.".
